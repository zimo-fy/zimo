# 招聘统一调度中心

## 🚫 绝对禁止（最高优先级，先于一切规则）

**严禁使用 `子 Agent` 委派"剩余候选人/剩余 N 条/未完成部分"。**
批量任务（例如回复 10 个候选人）必须在**当前会话内顺序处理完所有**。
理由：子任务结果**不会流回**用户聊天界面（runtime 限制：`streamTo:parent` 在 subagent runtime 不支持），spawn = 用户失联。
若上下文真的不够，**只能**输出：「已处理 N/M，请在新会话中继续处理后 M-N 条」让用户重新触发；**不要**自己 spawn 子任务。

## 概述

本 Skill 是所有招聘平台的**统一入口**。用户只需下达一条招聘指令，本 Skill 负责解析意图，然后**依次调用**对应平台的 Skill 完成操作。若用户是在创建长期招聘自动化任务，本 Skill 只负责把任务转给平台 planner，不直接执行长期流程。

## 核心调度规则

### 1. 解析用户指令

从用户消息中提取以下信息：

| 字段 | 说明 |
|------|------|
| **操作类型** | 长期招聘自动化任务 / 发布岗位 / 搜索求职者 / 推荐牛人打招呼 / 回复消息 / 查看简历 |
| **目标平台** | 指定平台名 或 全部平台 |
| **岗位/关键词** | 职位名称、搜索关键词 |
| **附加条件** | 城市、薪资、学历、经验等。⚠️ **薪资数字一律照搬用户原文字面值**: 用户写几位数就保留几位数, 用户带 k/K 单位就保留 k/K 单位, **禁止做任何简写 / 单位转换 / 位数压缩 / 万元换算** |

### 2. 平台匹配规则

**指定平台（精确匹配）：**
- 用户指令中**明确提到**某个平台名称或关键词 → 仅在该平台执行
- 示例：
  - "去 **boss直聘** 发一个前端开发的招聘" → 仅调用 `boss-zhipin` Skill
  - "帮我在 **鱼泡** 上搜一下电焊工" → 仅调用 `yupao` Skill
  - "去 **猎聘** 回复求职者消息" → 仅调用 `liepin-hr` Skill

**全平台（未指定平台）：**
- 用户指令中**未提及**任何平台名称 → 在所有已接入平台上依次执行
- 示例：
  - "帮我发一个招聘 前端开发 的岗位" → 依次在 Boss直聘、鱼泡直聘、猎聘网上发布
  - "搜索 Java 工程师并打招呼" → 依次在所有平台搜索并联系

### 3. 执行顺序

当需要在多个平台执行时，**按照已接入平台表的顺序依次执行**：

```
第 1 步：在 Boss直聘 上执行（调用 boss-zhipin Skill）
  ↓ 完成后
第 2 步：在 鱼泡直聘 上执行（调用 yupao Skill）
  ↓ 完成后
第 3 步：在 猎聘网 上执行（调用 liepin-hr Skill）
  ↓ 完成后
第 N 步：在 其他平台 上执行...
```

**⚠️ 不要并行操作多个平台。** 因为所有平台共享同一个浏览器实例，必须逐个平台完成后再切换到下一个。

## 长期招聘自动化任务

当用户表达的是“生成/创建一个会长期运行的招聘自动化任务”，而不是立即完成一次普通招聘操作时，必须进入本模式。

### 触发词

命中以下任一类表达：

- 自动化任务 / 长期任务 / 持续执行 / 定时执行 / 后台执行
- 自动打招呼、自动回复、自动收简历、自动筛简历、自动约面试
- “帮我招聘 X 人，持续打招呼回复，合适的推进面试”
- “生成一个招聘任务 / 招聘流程 / 招聘 agent 调用”

### 调度规则

1. 不直接调用 search/recommend/reply 开始执行。
2. 先调用目标平台的自动化 planner：
   - Boss直聘：读取 `当前已加载平台 Skill 的 instructions`，再进入 `tasks/automation-plan.md`
   - 鱼泡直聘：读取 `当前已加载平台 Skill 的 instructions`，再进入 `tasks/automation-plan.md`
3. planner 只输出结构化任务规划 JSON，不做浏览器操作。
4. 指定鱼泡时所有 capability 必须使用 `yupao-*`，指定 Boss 时使用 `boss-*`，禁止跨平台混用。
5. 用户未指定平台时默认优先 Boss。一次自动化任务只绑定一个平台；多平台需求拆成独立任务顺序执行，避免共享浏览器资源冲突。
6. 输出结果必须包含 `[AUTOMATION_PLAN_READY]`，供上层 Zimo Automation 创建任务和子流程。

### 自动化模式输出

收到长期自动化任务时，输出：

```text
收到，将为您生成长期招聘自动化任务规划：
- 平台：<平台>
- 任务：<用户原始需求摘要>
- 执行方式：先生成任务规划，不立即开始浏览器执行
```

然后读取平台 Skill 并进入 `tasks/automation-plan.md`。

## 🔔 修饰词不是新任务（先于触发词映射读，最高优先级）

用户在「推荐」或「搜索」任务里**附带**出现回复消息语义 —— 关键词：`顺便回` / `兼顾回` / `过程中回` / `同时回` / `边 X 边回` / `及时回消息` —— 这是**一个主任务 + 内联监听修饰词**，**不是两个任务**：

- 操作类型仍是「推荐牛人打招呼」**或**「搜索求职者」（唯一一个）
- **严禁**输出"先执行推荐、再执行回复"的两段式执行计划
- **严禁**先后调用平台的 recommend/search 任务再调用 reply 任务
- 正确做法：调用平台 SKILL → 直接进 `tasks/recommend.md` 或 `tasks/search.md`，其中已写好「兼顾回复求职者新消息」内联监听段，看到修饰词自动启用，每次 snapshot 检查菜单红点 → 有红点 → 内联跳 reply 处理几条 → 回主任务

正反例：

| 用户指令 | 任务数 | 说明 |
|---|---|---|
| "推荐 20 人，顺便回一下消息" | **1** | 推荐 + 内联监听 |
| "搜电焊工 10 个，过程中及时回消息" | **1** | 搜索 + 内联监听 |
| "先回几条消息，再推荐 10 人" | 2 | 用户显式两段顺序，不是"顺便" |
| "回复一下求职者消息" | 1 | 纯 reply 任务，无主任务 |

只要识别到主任务（推荐/搜索）+ 修饰词，**整段调度按 1 个任务执行**，传给平台 SKILL 的指令**完整保留**原始用户措辞（含"顺便/兼顾/过程中..."字样），下游 task 文件靠这些字样自动启用内联模式。

## 执行流程

### 步骤 1：解析指令

收到用户消息后，提取操作类型、目标平台、岗位关键词和附加条件。

**输出解析结果（告知用户执行计划）：**

```
收到！为您执行以下操作：
- 操作：<操作类型>
- 岗位：<岗位名>
- 平台：<目标平台>
- 附加条件：<城市、薪资、学历等>（数字一律照搬用户原文,不要简写 / 转单位）

即将依次在各平台执行，开始第一个平台：<平台名>...
```

### 步骤 2：依次执行各平台任务

按照平台顺序，调用对应 Skill 的对应任务。每个平台的具体操作步骤**完全遵循该平台 Skill 中的定义**，本调度 Skill 不重复定义具体操作。

**平台切换时输出提示：**
```
✅ Boss直聘 操作完成。
接下来切换到：鱼泡直聘...
```

（鱼泡完成后同理切换到猎聘网，猎聘完成后进入汇总。）

### 步骤 3：汇总结果

所有平台执行完毕后，输出统一汇总：

```
全部完成！操作汇总：

【Boss直聘】
- 已填写岗位信息：<岗位名>（<城市>，<薪资照搬用户原文>）
- 状态：等待用户确认并手动发布

【鱼泡直聘】
- 已填写岗位信息：<岗位名>（<城市>，<薪资照搬用户原文>）
- 状态：等待用户确认并手动发布

【猎聘网】
- 已填写岗位信息：<岗位名>（<城市>，<薪资照搬用户原文>）
- 状态：等待用户确认并手动发布
```

## 异常处理

| 异常情况 | 处理方式 |
|---------|---------|
| 某平台未登录 | 执行该平台的登录流程，登录成功后继续；登录失败则跳过该平台，提示用户 |
| 某平台操作失败 | 记录失败原因，跳过该平台，继续下一个平台，最终汇总中标记失败 |
| 用户指定的平台未接入 | 提示用户该平台暂未接入，列出当前已接入的平台供选择 |
| 某平台不支持该操作 | 跳过该平台的该操作，汇总中说明原因 |
