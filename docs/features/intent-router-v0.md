# Intent Router V0

状态：已实现，等待人工验收  
日期：2026-09-03

## 行为

每次发送或重新生成消息时，Router 在模型正文流开始前完成一次意图识别，并首先发送 `route.completed`。无论识别结果是普通聊天、目标命中还是安全降级，当前消息都继续进入原有聊天模型；V0.1 不执行 Agent、Skill 或 Workflow。

识别采用两阶段策略：

1. 明确调用词与唯一启用目标名称同时命中时，由本地规则返回 `0.98` 置信度；
2. 其余输入复用当前会话的 OpenAI-compatible 模型进行 JSON 分类；
3. 分类结果经过 strict Zod Schema、`0.7` 阈值、目标存在性、启用状态和目标类型校验；
4. 超时、调用错误、非法 Schema、低置信度或非法目标统一降级为普通聊天。

总分类预算为 800ms，超时只停止等待并降级继续聊天，不 abort 已发出的分类请求。用户取消仍使 Router 以 `AbortError` 失败（不转换成普通 fallback），并停止主回复模型；已发出的分类请求继续跑完以便补记 usage。

## 安全边界

- `shouldExecute` 在 Domain、Schema、规则、fallback、UI 和测试中均为字面量 `false`；
- 分类模型只得到消息文本及 Agent/Skill/Workflow 目标目录，不得到秘密或原型配置正文；
- Renderer 只得到最终安全 Route DTO，不得到分类 prompt、模型原始响应或 fallback 异常；
- `0003_intent_routes.sql` 只保存输入长度和 SHA-256 单向 fingerprint，不保存输入正文；
- 结构化日志只记录耗时、意图、目标 ID、置信度和 fallback reason。

## UI

聊天区显示本次识别结果、置信度和安全说明。命中目标时明确提示“功能将在后续版本开放”，并说明本次仍由普通对话回答；降级时显示 fallback 原因。用户可以关闭提示并继续普通对话。

## 已知限制

- 规则匹配目前只处理唯一、显式命名的目标；别名和模糊匹配留待后续评估；
- LLM 分类沿用当前会话模型，不引入独立 Router 模型设置；
- 800ms 对公网端点可能偏紧，超时会安全降级，不延长聊天阻塞时间；分类 HTTP 可在后台最多再等 60s 以补记 usage；
- 不包含授权确认、目标执行、多 Agent 或后台路由。
