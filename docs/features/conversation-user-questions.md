# 会话内结构化提问

## 范围

桌面窗口发起、模型支持 Tool Calling 的普通会话可调用 `ask_user_question`，在执行过程中向用户提出 1–3 个结构化问题。每题提供 2–4 个选项，支持单选、多选和“其他”自输入。Application 只向页面发布当前一题；用户提交后当前浮层立即关闭，再发布下一题。全部问题完成后，答案作为本次 Tool Call 的结构化结果一次性返回模型，原会话运行继续，不另建一条用户消息。

问答卡是消息输入框上方的独立非模态浮层，不嵌入或撑高输入表单。浮层沿用会话区域的中性色、圆角、阴影和按钮样式；多题时显示当前题号。Main 接受回答后 Renderer 立即移除对应卡片，同时继续消费 `question.resolved/requested` 事件，用于下一题推进和状态恢复。

当前不接入 Workflow 内部节点、微信入站和后台 Automation，也不提供跨应用重启的待回答恢复。会话切换或 Renderer 刷新可通过当前窗口的具名 IPC 重新读取等待卡；窗口销毁、用户停止、应用退出或 30 分钟超时使问题失效。已提交或失效的答案不能重放。

## 执行与权限

- 问题是用户对方案或参数的选择，不是文件、命令或其他副作用的批准。后续动作继续进入原有 `PlannedAction → ActionPolicy → ApprovalService` 链路。
- 如果一批模型 Tool Calls 同时包含提问与其他工具，其他调用本轮返回 `QUESTION_BATCH_DEFERRED`，不执行；模型收到用户回答后可重新调用。
- Tool 问题参数和 IPC 答案均经有界 Schema 与选项成员校验；每次 IPC 只回答当前一题，账号/窗口不能回答其他窗口或已经推进的问题。普通日志和审计不记录问题或答案正文；开发态敏感模型 payload 仍可能包含它们。
- 人工等待不使用普通 Tool 的短执行超时，但受 30 分钟等待期限与运行取消约束。没有可验证窗口的后台运行不暴露提问 Tool。

## 验证

单元测试覆盖逐题发布、答案汇总回传、选项校验、窗口隔离、一次性提交、取消、超时，以及同批副作用延后；Hook 回归覆盖 Main 接受后立即移除，组件测试覆盖多选和自输入。Preload 安全边界 Electron E2E 已通过；真实模型自主触发与完整问答交互仍需人工验证。
