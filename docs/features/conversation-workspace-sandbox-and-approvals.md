# 会话工作目录、持久目录授权与逐动作审批

> 状态：文件目录模型、授权策略及实验性宿主机命令已实现；OS 沙箱和受控网络仍暂缓
>
> 更新日期：2026-09-18
>
> 适用平台：macOS arm64/x64、Windows x64

## 1. 目标与阶段边界

在会话中提供默认 Zimo Workspace、外部目录授权、产品级文件 Tool 和实验性 `run_command`。命令通过可替换的 Main Adapter 在宿主机执行，不是 OS 沙箱；网络与外部应用 Tool 仍不注册。

本功能与早期 Phase 7.1 边界冲突，因此单列为 Phase 9。项目所有者已批准目录绑定、受控 Workspace Tool、策略模式、一次性审批、受控文本修改与逐级创建子目录，以及 OS 沙箱完成前的实验性宿主机命令。网络和外部应用仍须通过后续阶段门。

### 当前实现边界

- 每个会话自动创建不可移除的默认 `Zimo Workspace`，另可绑定最多 5 个外部目录；
- 用户选择的外部目录获得普通读写授权；授权按登录账号持久化，删除绑定同时撤销该账号的持久目录授权，但不删除用户文件；
- 原生目录选择和文件夹拖放仅在 Preload/Main 解析真实路径，Renderer 和模型只接收 opaque ID 与显示名；
- 模型每轮稳定获得 `zimo.workspace.list/search/read/create/mkdir/patch/delete`，目录内容仅在实际调用后有界返回；
- 未绑定目录允许按用户给出的绝对路径读取；首次写入先审批并自动记住其父目录，不需要再次打开系统选择器；
- `system/`、`accounts/`、生产安装目录和其中的数据库、密钥、日志、审计及安装资源始终拒绝；符号链接、敏感文件、依赖/构建目录、二进制和超限文本继续拒绝；
- 创建不覆盖已有文件；修改/删除要求读取所得 checksum，修改使用同目录临时文件原子替换，二者执行前保存受管恢复副本；
- `mkdir` 仅创建一个尚不存在的子目录，父目录必须先存在；复用文件写入授权与审批，不接受符号链接、敏感/排除目录或跨授权根路径，不隐式递归创建；
- 已有模式切换、一次性审批卡片和设置页只读审计中心；`run_command` 已开放，受控网络和恢复 UI 尚未开放。

### 本地目录布局

```text
userData/
├── system/
│   ├── secrets.enc
│   ├── logs/
│   └── workspace-recovery/
├── accounts/
│   └── local/
│       ├── zimo.sqlite            # Agent/Skill/知识库/会话等结构化数据
│       ├── knowledge-files/
│       └── skill-runtime/
└── workspaces/
    └── <conversationId>/
        ├── files/                 # 默认 Zimo Workspace 普通输出
        └── <artifactId>/...       # 附件与生成文档 revision
```

`accounts/local` 是当前单本地配置文件的账号数据容器；Agent、Skill、知识库、会话等结构化元数据和文件负载均进入该容器。未来若支持同一操作系统用户切换多套完全隔离的本地账号数据，需要独立 migration 按云端账号拆分 `local`，不能只靠改目录名伪装完成。

升级时 Main 在数据库打开前把旧 `zimo.sqlite`、`secrets.enc`、`knowledge-files`、`skill-runtime`、`document-workspaces` 和 `workspace-recovery` 原子迁移到新位置；目标已存在时不覆盖，避免静默丢失用户数据。

首版默认策略：

| 能力           | 默认行为                                                           |
| -------------- | ------------------------------------------------------------------ |
| 默认 Workspace | 会话创建后自动拥有；普通读写直接执行                               |
| 用户添加目录   | 读取和普通创建/小型修改直接执行；其他动作按会话审批模式处理        |
| 未授权目录     | 普通文本可读；不可直接写，批准写入后按账号持久授权该目录           |
| 命令执行       | 实验模式由 Main Adapter 以当前 OS 用户权限运行；按会话审批模式处理 |
| 网络           | 默认关闭；访问新域名需要逐次审批                                   |
| 内部目录       | Zimo 系统、账号数据和安装目录始终拒绝通用文件访问                  |
| 高风险操作     | “请求审批”人工确认；“帮我批准”自动执行                             |
| 关键危险操作   | 直接拒绝，不提供批准入口                                           |
| 授权范围       | 动作批准仍一次消费；目录写入授权按账号持久化，可主动撤销           |

“帮我批准”是当前会话的自动执行模式，会放行文件写入、删除和 `run_command` 等已注册、可执行动作。用户的最近选择按登录账号保存，新建任务和下次启动沿用；已有会话仍保存自己的模式，不会被后续账号偏好反向覆盖。它不注册网络或外部应用能力，也不能绕过路径逃逸、内部目录、敏感文件等 Adapter/策略硬拒绝边界。

## 2. 用户交互

### 2.1 添加工作目录

1. 用户在会话“+”菜单的附件区域下方点击“添加工作目录”，或把文件夹拖入聊天窗口；
2. Main 打开原生目录选择器，解析 canonical path 并完成符号链接、可访问性和根目录边界检查；
3. Renderer 只获得 `workspaceId`、显示名称、权限摘要和连接状态，不获得绝对路径；
4. 输入框下方以小型胶囊展示目录名称；“请求审批 / 帮我批准”下拉位于输入框底部工具栏、模型选择器之前；账号首次使用默认“请求审批”，此后新任务沿用该账号最近选择；
5. 未添加目录的普通读取无需绑定；首次写入会显示动作审批卡片，允许后自动持久授权对应父目录并继续原运行。

目录不会被复制到 Zimo 管理目录。绑定只授予受控 Tool 在该目录上的能力，不把目录正文自动塞进模型上下文，也不递归建立全量索引。

默认 `Zimo Workspace` 是附件、生成文件和普通输出容器，不与用户主动添加的项目目录竞争命令工作目录。会话存在外部目录时，编程、Git、构建和测试命令使用模型明确选择的外部目录；若模型误传默认 Workspace，则 Application 改用最近添加的外部目录。只有没有外部目录时，`run_command` 才回退默认 Workspace。

### 2.2 请求审批

当模型提出需要确认的结构化 Tool Call 时，会话运行进入 `waiting_for_approval`：

- 输入区上方显示固定审批卡片，包含动作类型、相对目标、影响摘要、风险原因和“一次允许 / 拒绝”；
- 文件修改展示有界 diff 摘要，命令展示经过 Schema 校验的完整命令与工作目录，网络展示目标域名；命令只保留于当前运行内存和审批事件，不写审计数据库；
- 审批卡片不得显示密钥、完整环境变量或超限文件正文；
- 允许后继续同一个 run，并把 Tool 结果返回模型；拒绝后把结构化拒绝结果返回模型，模型可改用安全方案；
- 关闭任务、取消生成或重启应用会使待审批请求失效，不得静默执行。

### 2.3 两种模式

- **请求审批**：读取直接运行；账号已放行目录内的普通低风险创建/修改直接运行，首次写入其他目录及高风险操作询问或拒绝。
- **帮我批准**：自动放行文件写入、删除和每条宿主机命令，不显示审批卡；关键危险动作、路径边界违规和未注册能力仍拒绝。网络和外部应用 Tool 尚未注册。

模式切换只影响后续动作，不追溯批准已等待的请求。首次目录外写入的动作批准仍绑定 `approvalId + actionDigest + runId`；成功形成的目录授权按登录账号持久化，并可在设置 → 审计中心的“已放行目录”中撤销。撤销会移除同根外部 grant，但不删除用户文件。

模式本身同时写入当前会话的全部 workspace grant 和账号级偏好。重新打开既有会话时以会话 grant 为准；创建新会话的默认 Workspace 时读取账号偏好。未登录、首次登录或没有偏好记录时失败关闭为“请求审批”，不同账号之间不得共享选择。

## 3. 运行架构

```text
用户消息
  -> 模型返回结构化 Tool Call
  -> Capability Registry（工具是否已注册）
  -> Action Planner（规范化路径、命令、域名和影响）
  -> Policy Engine（allow / ask / deny）
       -> deny：记录审计并返回受控错误
       -> ask：暂停 run，等待一次性审批
       -> allow：进入执行
  -> Main 文件 Adapter 或 WorkspaceCommandExecutor
  -> 本地文件系统 / 宿主机固定 Shell
  -> 输出归一化、大小限制和审计
  -> Tool Result 返回模型继续推理
```

Renderer 不接触 Node、Shell、真实路径或执行器。模型不能选择 IPC channel，只能调用注册 Tool。`run_command` 的起始目录来自当前会话 workspace ID，但命令获批后并不会被 cwd 限制，仍可读取或修改当前 OS 用户可访问的位置；这正是后续必须用 Sandbox Adapter 替换的临时边界。

建议新增领域边界：

- `WorkspaceGrant`：会话与已授权目录根的关系；
- `PlannedAction`：对 Tool Call 规范化后的不可变动作；
- `ActionPolicyDecision`：`allow | ask | deny`、风险和规则版本；
- `ApprovalRequest`：待确认动作及一次性 digest；
- `SandboxExecution`：执行请求、取消和受限结果；
- `AuditEvent`：不含正文和秘密的事实记录。

## 4. 首版 Tool 集合与 Token 策略

模型只看到少量稳定的产品级 Tool，而不是所有 Node API 或 shell 子命令：

| Tool                         | 用途                | 默认风险               |
| ---------------------------- | ------------------- | ---------------------- |
| `zimo.workspace.list`        | 有界列出目录项      | 低                     |
| `zimo.workspace.search`      | 按 glob/文本搜索    | 低                     |
| `zimo.workspace.read`        | 分页读取文本文件    | 低                     |
| `zimo.workspace.patch`       | 精确文本替换        | 中；可被低风险规则降级 |
| `zimo.workspace.create`      | 创建新文件          | 中；可被低风险规则降级 |
| `zimo.workspace.mkdir`       | 逐级创建子目录      | 中；复用文件写入授权   |
| `zimo.workspace.delete`      | 删除文件            | 高；按会话审批模式处理 |
| `zimo.workspace.run_command` | 运行任意 Shell 命令 | 高；按会话审批模式处理 |

Tool Schema 接收 `workspaceId + 相对路径`，或在未绑定读取/首次写入时接收单一 `absolutePath`。目录树和文件正文仅在模型实际调用后分页返回；绝对路径不进入普通日志和 append-only 审计事件。设置页已放行目录清单从账号授权表读取真实位置，供用户识别和撤销。模型上下文只接收 workspace ID、显示名和 `用户项目目录/Zimo 内部输出目录` 类型，不接收真实根路径。

模型只看到一个 `run_command` Tool，不会为 git、pnpm、Python 等子命令分别增加 Tool。命令支持平台 Shell 的组合语法；当前不提供单独打开 URL 或调用桌面应用的 Tool。

### 实验性宿主机执行边界

- macOS 固定使用 `/bin/zsh -l -c`，Windows 固定使用 `powershell.exe -NoProfile -NonInteractive -Command`；Node 以 `shell:false` 启动明确的 Shell；
- 默认超时 120 秒、最大 360 秒；会话取消会终止进程树；stdout/stderr 各保留有界首尾内容；
- 子进程只继承运行所需的有限环境键，不直接继承 Zimo 模型、登录和 MCP 凭据；Shell 启动文件或命令主动读取本机文件仍可能获得用户秘密；
- 非零退出码、信号、超时、截断和耗时作为结构化 Tool 结果返回模型；
- 当前没有文件系统、网络、进程或资源的 OS 强制隔离，不得用于无人值守运行或宣传为安全沙箱。

## 5. 风险判定基线

| 等级     | 示例                                                       | 请求审批                 | 帮我批准 |
| -------- | ---------------------------------------------------------- | ------------------------ | -------- |
| 低       | 读取普通源码；创建新文件；对已有文件应用小型、可回滚 patch | 读直接放行；写按授权规则 | 自动放行 |
| 中       | 覆盖较大文件；批量修改；运行项目脚本；写入构建配置         | 询问                     | 自动放行 |
| 高       | 删除；改锁文件或启动脚本；任意 `run_command`               | 询问                     | 自动放行 |
| 关键危险 | 文件 Tool 的目录逃逸、内部数据访问、敏感目标或策略绕过     | 拒绝                     | 拒绝     |

实验性 `run_command` 当前不解析命令内容，也无法可靠识别提权、磁盘破坏、凭据读取或持久化行为；它们统一落入“高风险、人工确认”。这比目标安全模型更弱，是明确记录的临时残余风险。

判定基于规范化后的结构化动作，而不是从自然语言或模型解释中猜测。远端 Tool 的风险声明、仓库内说明和模型自报风险都只是不可信提示。

## 6. OS 沙箱含义

“只在 OS 沙箱中执行”表示命令运行在与 Electron Main 分离的受限进程中，并由操作系统强制限制：

- 文件系统只映射显式工作目录和必要的只读运行时；
- 网络默认不可达，批准域名通过受控代理或平台网络规则开放；
- 清空模型不可见的环境变量，不继承 Token、API Key、Cookie 和应用内部路径；
- 禁止提权、调试/注入其他进程、设备访问和持久化；
- 使用进程组/Job Object 管理超时、取消、子进程和退出清理；
- 限制 CPU、内存、输出、文件数量和运行时间。

仅做 `path.startsWith(root)`、设置 `cwd`、使用 Electron Utility Process、`shell:false` 或执行前字符串黑名单，都不是完整 OS 沙箱。平台候选、不可接受方案和验证矩阵见[Phase 9 OS 沙箱技术 Spike](../reports/phase-9-os-sandbox-spike.md)。

5. 完成秘密 canary、恶意仓库、Prompt 注入、审批疲劳和恢复测试；
6. 完成 macOS/Windows 干净安装、签名包、升级和回滚验证。

门禁：产品、安全和跨平台人工验收完成后，Phase 9 才能标记可用。

## 8. 验证范围

- Domain：风险矩阵、模式差异、始终询问/始终拒绝、不可信声明；
- Contracts：IPC、事件、路径/argv/domain Schema、未知字段拒绝；
- Application：暂停恢复、防重放、取消、超时、并发和单终态；
- Adapter：canonical path、symlink、TOCTOU、原子写、进程树、资源上限；
- SQLite：空库、`0024 -> 0025+`、回滚、过期审批恢复和级联删除；
- Renderer：键盘/焦点、审批可读性、长命令、窄窗口、任务切换；
- E2E：添加目录、读、改、拒绝、批准、取消、重启和审计检索；
- 安全：目录逃逸、环境泄密、网络外带、命令注入、审批伪造和日志 canary；
- Package smoke：macOS arm64/x64、Windows x64 的签名包与真实沙箱 helper。

## 9. 首版明确不做

- 全盘或 Home 目录写入授权；
- 命令前缀记忆；目录授权只记住普通文件读写边界；
- 后台无人值守的宿主机命令执行；“帮我批准”仅作用于当前会话的前台运行；
- 远程后台无人值守命令；
- 任意桌面应用自动化、键盘鼠标控制或系统权限修改；
- 容器/虚拟机级隔离承诺；
- 把仓库内容当作可信指令；
- 让模型自行更改权限策略、审计记录或沙箱配置。
