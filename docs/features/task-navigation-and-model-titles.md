# 任务导航与模型标题

状态：已实现  
日期：2026-09-17

## 用户体验

Zimo 将已有 Conversation 直接作为侧栏“任务”，不新增重复的任务实体或持久化表。登录后，任务区固定在主菜单与账户区之间；空间不足时只滚动任务区。仓储层按 `is_pinned DESC, updated_at DESC` 排序，置顶任务始终在普通任务之前，同组内最近有活动的任务在前。

- 点击任务复用现有聊天页、消息流、能力绑定和模型选择；
- 一级“新建任务”和任务区“+”打开同一个空白草稿会话；
- 空白草稿保留“今天想聊些什么？”引导，提示用户可先选择模型、Agent 与资料再描述任务；
- 草稿 Conversation 不进入任务列表，第一条指令发送成功后才转为当前任务并显示在列表中；
- 每项以“标题 + 右侧更新时间”单行展示；置顶任务在标题前显示小型图钉状态标识，普通任务不占用图标空间；
- hover 或键盘聚焦时隐藏时间并显示 `…`，菜单支持置顶/取消置顶、修改名称和确认后软删除；
- 聊天标题栏只显示当前标题，不重复放置重命名和删除入口；
- 删除当前任务后选择下一条最近任务，没有剩余任务时展示空状态；
- 窄侧栏隐藏任务列表，避免在没有标题空间时用无语义图标代替任务。

主导航不再展示“概览”，“对话”改为“新建任务”，登录后直接进入空白草稿。菜单文字统一为 14px，当前项使用与图标一致的浅色背景和深色文字，避免大面积纯黑选中态。打开已有任务时，新建入口不保持选中。

“工具”保持单个一级入口，点击后从侧栏右侧弹出知识库、工作流、通信渠道、MCP 和自动化菜单，不再纵向展开挤占任务列表。会话已选择的 Agent、直接 Skill、知识库、Workflow 与 MCP Server 使用紧凑标签展示；鼠标移入或键盘聚焦标签时显示移除按钮并解除真实绑定。Agent 内继承的 Skill 不单独显示成可删除标签，避免制造错误的独立授权语义。默认 Zimo Workspace 在后台继续生效，但不在输入区展示；用户显式添加的外部工作目录仍展示并可移除。

侧栏底部不再单独占用“设置”菜单；点击 Zimo 账户后，可从账户菜单进入设置或退出登录。

## 模型标题

空白草稿先以“新对话”持久化，以便首条指令前即可选择模型和会话能力，但按 `messageCount === 0` 从任务列表隐藏并在下次启动复用。第一轮助手正文生成完成后，Application 使用本轮模型发起一次独立标题请求，只提供首条用户文本，并要求返回简短纯文本标题。标题请求不设置短于普通模型请求的专用超时，继续响应会话取消和模型网关统一失败边界。标题经去 Markdown、引号、标签和尾部标点处理，最长保存 30 个可见字符；模型失败或返回空标题时，从首条指令生成最多 24 个字符的本地兜底标题。

标题生成遵守以下规则：

1. 仅处理标题仍为“新对话”且只有一条用户消息的任务；
2. 写入前重新读取 Conversation，用户在生成期间手动改名时不覆盖；
3. 模型返回失败或空标题时使用本地兜底；会话取消、模型或凭据不可用不把已成功的主回答改为失败；
4. Workflow 会话使用该 Conversation 的模型，普通/Agent 会话沿用本轮实际模型；
5. 标题调用会产生一次额外模型请求和对应 Token 消耗。

## 日志与边界

普通日志写入 `model.request.prepared` 和 `conversation.title.generated`，只包含请求用途、模型 ID、消息字符数、耗时、结果与错误码，不包含用户文本或标题。开发态敏感日志中的标题请求使用 `purpose: "task_title"`，正常回答使用 `purpose: "conversation_response"`。

Renderer 只调用严格的 `window.zimo.conversations` API，不接触数据库、模型网关或密钥。置顶通过 `conversations:set-pinned:v1` 写入 `conversations.is_pinned`；该操作不更新 `updated_at`，避免改变同组的真实最近活动顺序。
