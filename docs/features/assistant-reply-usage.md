# 助手回复用量展示

状态：已实现  
日期：2026-09-21

## 目标

助手气泡内部底部展示本次发送相关的 token 消耗和该条回复生成时的模型显示名；完成/停止/失败时刻移到气泡下方的常显时间。元信息覆盖完成、已停止和失败消息。模型名在创建助手消息时写入 `messages.model_display_name`，之后切换输入区模型不会回写历史消息。升级前已存在且该列为 NULL 的回复省略模型名，不用当前选择回填。

## 计入范围

「共消耗」是这条助手消息上 `usage` 的合计，优先 `totalTokens`，否则 `inputTokens + outputTokens`。同一轮发送会合并：

1. 主回复流式或 Tool 各轮（一轮内部最后一份 usage 覆盖，轮与轮相加）；
2. Router 分类 `invoke`（含 800ms 超时后仍在后台完成的那次）；
3. 首轮任务标题生成。

有 Agent/Workflow 或规则命中时不调分类，也就没有分类用量。提供商未返回时省略消耗文案，不伪造 `0`。缓存 token 已含在 input/total 中，不再加一遍。

## 超时与停止

- 分类超过 800ms：聊天立即按普通对话继续，**不 abort** 这次 `invoke`。分类 HTTP 上限 60s，与补记等待对齐；800ms 只决定何时降级继续聊天。请求结束后把 usage 合并进同一条助手消息，并再发 `usage.updated`（带 `messageId`）。
- 用户中途停止：主回复立刻停字并标已停止，**不立刻 abort** 当前这条模型 HTTP。Main 继续读 SSE 直到 usage / `[DONE]`，或最多 15s，再把用量合进同一条助手消息。已发出的分类请求仍等 usage 回来再补。
- 正在流式、drain 后仍没有 `usage_metadata` 的半轮：不估算。

## 不计入

连接测试、压缩卡片估算、其它会话、Workflow 内部节点。后台计费口径（缓存折扣）可能和四行 input+output 之和不同。

## 界面

气泡内部：`共消耗 {n} tokens · {生成时模型显示名}`；气泡左下方：`{HH:mm}`。无快照时只展示消耗（若有），不显示模型名。

已停止/失败时在用量上方显示状态文案。时间用消息 `updatedAt`（完成、停止或失败时刻）；流式输出期间用 `createdAt`，补记 usage 不改时间。

每条已完成、已停止或失败的助手回复，在用量右侧提供重新生成。悬停提示「点击将重新生成内容，此会话后的内容都将被覆盖，请谨慎操作」。运行中或正在压缩时不显示。输入区原有重新生成仍可用，默认针对最后一条助手回复。重新生成创建新的助手消息并关联 `replacesMessageId`，模型上下文取被替换回答之前的历史；Renderer 会隐藏该槽位之下、重新生成开始前已存在的后续消息，重新生成完成后用户新发送的消息仍正常显示。

## 验证

- Router：超时不 abort 分类、延迟 usage 可收获、用户取消不 abort 分类。分类 HTTP 上限 60s。
- 停止后立刻停字并标已停止；当前模型 HTTP 再读最多 15s。
- Drain 后仍可按 `messageId` 补记；Tool 轮取消不执行后续工具，但保留本轮 usage。
- `usage.updated` 可按 `messageId` 写回已完成/已停止消息；`run.cancelled` 把进行中助手标为已停止并保留 usage。
- 组件测试覆盖有用量/无用量文案。
- 每条终态助手回复均显示重新生成；悬停提示后续内容会被覆盖。
