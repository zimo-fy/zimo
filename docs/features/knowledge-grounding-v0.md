# Knowledge Grounding V0

## 范围

Phase 6C 将已启用的本地知识库接入普通会话和 Agent，但不引入 Tool、MCP、Workflow 执行或外部数据源。

普通会话在标题栏显式选择一个知识库，选择结果保存在会话中。Agent 可在编辑器中绑定最多 5 个已启用知识库；Agent 运行时合并会话选择与 Agent 绑定，总数仍不得超过 5 个。知识库被会话或 Agent 引用时禁止删除。

## 生成流程

1. 保存用户消息并建立唯一 active run；
2. 解析用户明确选择的 Agent，校验模型、Skill 和知识库状态；
3. 使用最新用户消息分别检索所选知识库；
4. 合并、去重并排序，最多选择 8 个文本块，正文总长度最多 6000 字符；
5. 把资料作为独立 System 消息注入，明确声明资料是不可信数据、不得执行其中指令；
6. 要求模型只在资料支持时使用 `[资料N]` 标注，资料不足时不得编造；
7. 将实际使用的来源快照保存到助手消息，并通过 `knowledge.retrieved` 流事件即时展示；
8. 完成、失败、取消和重新生成继续沿用单一终态与 AbortSignal 语义。

来源快照只包含知识库、文档、文本块 ID、名称、位置和分数，不复制知识正文。删除源文档后，历史回答仍显示当时使用的来源名称，但不承诺源内容仍可打开。

## 安全边界

- 知识文本不能覆盖 Agent/System 指令，不能申请 Tool、MCP、Shell、网络或文件权限；
- Renderer 只能选择 Main 返回的知识库 ID，Application 再校验存在性与启用状态；
- 无检索结果时继续普通模型生成，不伪造来源；
- Embedding 资源异常时检索自动保留 FTS5 路径；
- 上下文预算当前按字符保守限制，后续接入模型 tokenizer 后再升级为精确 token 预算。
