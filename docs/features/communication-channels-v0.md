# 通信渠道 V0

## 已实现

- 主导航 `Plugin` 改为“通信渠道”，内置个人微信 Clawbot 和邮箱两项；
- 微信按腾讯 OpenClaw Weixin channel 的 QR 登录协议生成应用内二维码，显示 5 分钟倒计时，轮询扫码、验证码、确认和过期状态；
- 邮箱只登记一个经过格式校验和规范化的邮件地址，不要求密码、授权码或 SMTP 配置；
- `0010_communication_channels.sql` 创建绑定表，`0011_email_address_binding.sql` 允许邮箱绑定不含秘密引用；
- Renderer 输入经过严格 Schema 校验，Main 网络操作带超时，微信跳转目标使用 HTTPS 域名白名单；
- 绑定和解绑写入不含秘密的审计日志。
- 微信绑定按当前登录账号隔离，应用启动恢复登录后开始可取消的 `getupdates` 长轮询；
- 有界文本进入每个账号专用的“微信助手”普通会话，模型结果通过原入站 `context_token` 回复；
- 游标和最近上下文保存在 SecretStore，SQLite 保存不含正文的去重收据；通信渠道页展示真实运行状态并提供测试消息。

## 微信实现说明

`@tencent-weixin/openclaw-weixin-cli` 只负责把实际插件安装进 OpenClaw，并要求本机已有兼容的 OpenClaw CLI/Gateway。Zimo 没有引入这条 shell 安装链，而是把已审计的 QR 登录协议封装成固定端点 Adapter；这样打包应用可独立工作，也不会在用户机器上执行 `latest` 包。协议常量以腾讯当前开源 channel `2.4.8` 为兼容基线，升级必须经代码评审和回归测试。

微信确认后保存 bot token，绑定元数据保存 bot/user ID 与 HTTPS base URL。监听只在对应 Zimo 登录账号活动时运行；长轮询响应先做大小和结构校验，再提取文本、稳定去重键和 `context_token`。每条回复使用其原始上下文，最近一次上下文仅供用户手动发送测试消息。没有收到过微信消息时不能主动推送，页面会提示先从微信发一条消息激活。

“微信助手”会话会显示在普通会话列表中，但初始不绑定 Agent、Skill、知识库、Workflow 或 MCP。来自微信的文字只作为普通用户消息处理，不会解释为远程授权或能力切换命令。登录账号切换、退出、解绑和应用退出会取消轮询和正在生成的该渠道回复；临时网络错误采用有界退避，登录凭据失效时停止并要求重新绑定。

## 邮箱实现说明

邮箱绑定仅保存规范化后的完整邮件地址，例如 `name@example.com`。Zimo 不登录该邮箱，也不保存邮箱密码、授权码、SMTP/IMAP 主机或端口。旧版 SMTP 绑定在用户重新添加邮箱时会清理原 SecretStore 凭据；数据库升级保留旧绑定，避免迁移期间丢失用户选择。

“已绑定”当前表示地址已登记，不表示 Zimo 已经能够读取该邮箱。后续如果要让用户从其他邮箱向该地址发送指令，需要单独实现 IMAP/OAuth 或受控邮件入站服务，包括发件人授权、轮询/推送、消息去重、附件限制、会话映射和回复策略。

## 后续接入 Workflow

1. 增加通知模板与最大正文限制；
2. 为 Workflow 增加显式“通知”节点或完成后通知策略；
3. 邮件发送 Adapter 使用独立的发件服务配置，不能把用户登记的收件地址当作发件凭据；
4. 增加用户确认、限流、超时、取消、失败重试与审计；
5. 邮件入站先确定 IMAP/OAuth 或邮件入站服务方案；微信需继续验证 `context_token` 的真实过期窗口与主动通知策略；
6. 投递失败不回滚已完成的 Workflow，只记录通知终态并允许手动重试。

## 当前限制

- 尚未从 Workflow 或普通会话自动发送通知；测试消息仅复用最近一次微信入站上下文；
- 邮箱目前只登记地址，尚未接入邮件收取、发件人验证、IMAP/OAuth 或入站 Webhook；
- 微信协议由腾讯服务控制，服务端变更可能要求升级兼容层；
- 未开放动态通信插件、Telegram、图片/文件/群聊入站或微信侧能力选择；监听只随本地应用与登录会话存活，不是系统后台服务。
