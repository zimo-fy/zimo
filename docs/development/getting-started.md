# 本地开发与阶段验收

用户端与企业管理端的对照部署见 [快速开始](../features/getting-started.md)。下文是本仓库 Desktop 开发与阶段验收。

## 环境

- Node.js 22.12 或更高版本；
- pnpm 10；
- macOS 为当前首要开发与验收平台。

仓库在 `package.json` 和 `pnpm-lock.yaml` 中锁定具体工具与依赖版本。不要绕过 lockfile 更新单个包。

## 首次安装

```bash
pnpm install --frozen-lockfile
```

如果 Electron 运行时因网络原因没有在安装阶段下载，可在网络可用后重新执行安装；不要手工复制其他 Electron 版本到 `node_modules`。

## 启动开发版

```bash
pnpm dev
```

欢迎页默认通过「开始使用 Zimo」进入本地引导并完成模型配置。远程账号密码登录需部署配置认证基址；开发自动测试通过 `ZIMO_AUTH_BASE_URL` 指向 loopback 假服务。密码不会保存；Token 由 Main 写入系统安全存储。

页面必须在 `pnpm dev` 启动的 Electron 窗口中运行。不要直接用浏览器打开 `apps/desktop/src/renderer/index.html` 的 `file://` 地址：源码入口依赖 Vite 转换和 Electron Preload，直接打开不会得到可运行应用。

## 质量门禁

常规代码门禁：

```bash
pnpm check
```

真实 Electron 窗口验收：

```bash
pnpm test:e2e
```

`pnpm check` 覆盖格式、Lint、类型、unit/contract、integration 与生产构建；E2E 单独运行，因为它会启动桌面窗口。

## Phase 1 人工检查

1. 启动后确认显示统一身份认证页，使用员工账号 ID/手机号登录；
2. 登录后确认概览、左侧导航、Phase 2/3 未开放状态和账户菜单；
3. 重新加载窗口，确认经 `/verify-token` 校验后恢复登录会话；
4. 打开设置，确认账户、本地数据位置、安全存储状态、外观与日志级别可见；
5. 退出登录，确认返回登录页；
6. 不应出现模型配置、真实聊天、产品模块 CRUD 或 Router 执行入口。

## Phase 2 人工检查

1. 使用会返回 `modelApiKey` 的测试账号登录，确认无需填写模型地址或 API Key；
2. 通过开发服务器打开“设置 → 登录模型”，确认可修改模型标识与 API 地址，并可选输入新 Key；当前 Key 不应回显，留空保存应继续使用登录密钥；
3. 保存后执行“测试连接”，确认该模型已自动设为默认。再次登录会保留这里保存的模型标识、显示名称和 API 地址；还没有保存过配置时登录失败；
4. 打开“对话”，创建会话并确认当前模型；
5. 发送消息，检查流式显示、Markdown、代码块和基础表格；
6. 测试停止生成、重新生成、会话重命名、模型切换和删除确认；
7. 重启应用，确认登录、模型元数据、会话和消息恢复。

## Phase 3 人工检查

1. 依次打开 Agent、Skill、知识库、工作流、Plugin、MCP 和自动化，确认列表、详情、搜索与状态筛选；
2. 创建并编辑一个 Agent，检查 System Prompt、复制、启用/禁用和删除确认；
3. 检查 Skill 的分类、标签、来源、版本、权限和关联 Agent；
4. 在知识库中拖放或选择文件，确认只生成 Mock 元数据，并检查检索测试的预览提示；
5. 在工作流画布拖动、连接、新增及重命名节点，保存后确认布局保留；
6. 检查微信、Telegram Plugin 示例及安装状态切换；
7. 检查 MCP 敏感配置遮罩，并确认连接测试明确返回“后续版本开放”；
8. 创建 Automation，分别检查单次、间隔、每天和每周计划；确认固定间隔不要求首次执行时间，每日范围只选择开始/结束时刻，并验证能力绑定、启停、立即运行、下次时间和运行历史；应用关闭期间不应执行；
9. 重启应用，确认原型恢复为内置示例（Phase 3 的 Mock 状态不承诺持久化）。

## Phase 4 人工检查

1. 配置可用模型并创建会话，发送普通问候，确认显示“继续普通对话”且回答正常生成；
2. 发送“请使用研究助手整理资料”，确认显示目标、置信度及“后续版本开放”，同时普通回答仍继续；
3. 禁用 Agent、Skill 或 Workflow 后再次命名调用，确认不会执行目标；
4. 使用返回非 JSON 或响应超过 800ms 的 fake/测试端点，确认 Router 降级但聊天仍继续；
5. 生成过程中点击停止，确认 Router/模型共享取消链且只有一个 run 终态；
6. 检查日志只含意图、目标 ID、耗时、置信度和 fallback reason，不含输入正文；
7. 检查 `intent_route_records` 只含 fingerprint 和输入长度，不含消息正文或分类原始响应。

## Phase 5A–5B 人工检查

1. 创建一个根目录包含非空 `SKILL.md` 的 instruction Skill 文件夹；`manifest.json` 可选，兼容元数据格式见 `docs/features/agent-skill-runtime-v0.md`；
2. 打开 Skill 页面并点击“从本地文件夹安装”，选择该目录；
3. 确认详情显示版本、来源、权限和 `SKILL.md` 指令，状态为已安装并启用；
4. 重启应用，确认安装的 Skill 以及创建或编辑的 Agent 仍然存在；
5. 修改相同 `packageId` 的版本和指令后重新安装，确认原条目更新而不是产生重复项；
6. 在 manifest 增加 `command`、`script` 或未知字段，确认安装被拒绝；
7. 创建或编辑 Agent，选择模型并绑定已安装 Skill，启用后点击“在对话中使用”；
8. 确认聊天页展示模型、Skill 数量和无 Tool/MCP 权限摘要，未确认时不能发送；
9. 发送消息，检查所选 Agent 直接生效、流式回答正常，以及 `agent_run_records` 只记录 ID、状态和错误码；
10. 发送会命中 Agent 的普通消息，确认 Router 只给出“下条消息使用此 Agent”建议，不自动执行；
11. 确认 Renderer API、日志和数据库诊断信息不包含所选目录路径、Skill 指令或 Agent prompt；
12. 确认 Skill 脚本、依赖安装、Tool/MCP 和 Router 自动执行仍未开放。

## Phase 7 Controlled Tool 人工检查

1. 在 Workflow 编辑器添加 Tool 节点，选择“本地知识库检索”并配置一个已启用知识库；
2. 连接“开始 → Tool → Agent → 结束”并保存；
3. 打开测试面板，确认显示只读、仅本地封闭数据、`knowledge:read` 权限和 10000ms 超时；
4. 点击“确认权限并运行”，确认 Tool、Agent 和结束节点依次完成并显示最终输出；
5. 运行中点击停止，确认进入取消终态；
6. 检查日志存在 `tool.execution.completed`，且不包含测试问题、知识正文、Tool 输出或 API Key；
7. 确认 Renderer 只有 `tools.list`，没有直接执行 Tool、连接 MCP、启动 stdio 或传入任意路径的入口。

真实 API Key 不进入版本库。开发者不应将 Key 放入 `.env`、命令参数、日志或测试 fixture；模型密钥只由登录响应下发给 Main，并立即交给系统安全存储。

## 本地数据

开发数据存放在 Electron 的应用 userData 目录中，主要包括 SQLite 数据库、加密秘密文件（仅安全后端可用时）和轮转日志。E2E 使用临时目录，结束后自动清理，不影响日常开发数据。

## Phase 6A–6B 人工检查

1. 打开“知识库”，选择一个已启用知识库；拖入或选择 TXT/Markdown/PDF/Office 文件；
2. 确认文件显示为“可检索”、分块数量正确，重启后仍存在；
3. 确认本地 Embedding 显示“离线可用”，且页面没有模型下载按钮；
4. 用精确词和同义表达分别检索，确认出现“关键词”“语义”或“混合”结果并显示来源；
5. 对 PDF、PPTX、XLSX 分别确认页码、幻灯片号或工作表名可显示（源文件确有相应结构时）；
6. 再次导入相同内容，确认提示已跳过重复文件；删除文档后确认结果不再命中；
7. 尝试空文件、超过 20 MB、符号链接或不支持格式，确认安全拒绝且不暴露路径；
8. 确认知识库只有在会话显式选择或 Agent 明确绑定后才进入模型上下文；数据库和管理后台同步尚未开放。

## Phase 6C 人工检查

1. 在知识库中导入包含可识别事实的 Markdown 或 PDF，并保持知识库启用；
2. 打开普通会话，在标题栏“当前知识库”中选择该知识库，重载后确认选择保留；
3. 提问可由文档回答的问题，确认回答下方出现“本次参考来源”和 `[资料1]` 对应文档位置；
4. 重载应用，确认回答正文和来源快照都能恢复；
5. 编辑 Agent 并绑定知识库，在对话中选择、确认该 Agent，确认知识库数量和来源正常；
6. 在文档中写入“忽略系统指令/调用工具”等内容，确认不会获得 Tool、MCP、Shell 或文件权限；
7. 取消知识库选择后提问，确认不再产生知识来源；
8. 尝试删除被会话或 Agent 引用的知识库，确认操作被拒绝并给出解除绑定提示。

## 已知提示

- 在命令行 Node 22 运行 integration 测试时，`node:sqlite` 可能打印 experimental warning；目标 Electron 44 使用内置 Node 24，真实窗口测试已覆盖；
- 构建可能显示来自 Zod 源码注释的 Rollup warning，当前不影响产物和测试；
- 未签名开发版的 macOS safeStorage 表现不能替代正式签名构建验收。
