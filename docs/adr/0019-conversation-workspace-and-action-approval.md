# ADR-0019：会话工作目录与逐动作审批

- 状态：Accepted；增加临时实验性宿主机命令执行，OS 沙箱仍待替换
- 日期：2026-09-18

## 背景

Zimo 现有会话文档能力只操作导入后的受管 artifact，受审核 Skill 脚本也不是恶意代码沙箱。面向编程协助，需要让会话访问用户明确选择的项目目录、修改文件并运行项目命令。直接把 Node 文件系统、Shell 或绝对路径开放给模型，会破坏 Renderer → Preload → Main → Application 边界，并扩大 Prompt 注入、路径逃逸、密钥泄露和破坏性命令风险。

## 决策

Phase 9 采用“受控 workspace 文件能力 + action-level approval”。项目所有者于 2026-09-17 明确批准在 OS 沙箱完成前增加实验性宿主机命令执行，用于验证编程 Agent 体验：

1. 应用数据归入 `system/`、`accounts/`、`workspaces/` 三个顶层目录；每个会话自动拥有 `workspaces/<conversationId>/files` 默认工作区，附件与生成文档也归入该会话的 workspace 容器；
2. 用户通过 Main 原生选择器添加的外部目录获得普通读写权限；Renderer 只接收 opaque workspace ID 与显示名；
3. 未添加目录允许通过 Workspace Tool 按绝对路径读取普通文本；首次写入必须审批，批准后按登录账号持久记录目录授权，后续会话不再为同一普通低风险写入重复授权；
4. `system/`、`accounts/`、生产安装目录、数据库、密钥、日志、审计数据和安装资源始终拒绝通用文件 Tool；敏感文件名、链接、二进制、可执行文件及预算限制继续适用；
5. 模型只能调用注册的产品级 Workspace Tool；文件写入、逐级创建子目录和命令 Tool Call 先规范化为 `PlannedAction`，再由策略引擎判定；
6. 账号首次使用默认显示“请求审批”；用户切换后按登录账号保存最近选择，新建任务和下次启动沿用该偏好，既有会话继续保留各自模式；默认工作区和账号已授权外部目录内的普通创建/小型修改直接执行，首次写入其他目录仍按当前模式处理；“帮我批准”会自动放行文件写入、删除和命令等当前可执行动作，关键危险动作、路径边界违规和未注册能力仍拒绝；
7. 文件操作在 Main Adapter 再次校验 canonical path、链接、类型、预算和 checksum；不把“路径受控”描述为 OS 沙箱；
8. `run_command` 通过可替换的 `WorkspaceCommandExecutor` 端口调用宿主机固定 Shell；它不是沙箱，命令拥有当前 OS 用户权限；所有命令均标记高风险，“请求审批”逐次确认，“帮我批准”自动执行；
9. 命令默认 120 秒、最大 360 秒，限制 stdout/stderr、支持取消和进程树终止，并以最小环境启动；非零退出码和超时以结构化结果返回模型；
10. 网络和外部应用 Tool 仍不注册；宿主机命令本身可以主动联网或访问目录外文件，这是当前明确接受的临时残余风险；后续 OS 沙箱通过后只替换执行 Adapter；
11. 策略判定、审批和执行终态写入脱敏审计存储。审批卡在当前运行内存中显示完整命令；审计中心只记录“执行命令”、工作目录显示名和相对 cwd，不保存完整命令、stdout/stderr 或环境变量。
12. 默认 `Zimo Workspace` 只作为附件/输出容器和无外部目录时的命令回退。只要会话存在用户选择的外部目录，`run_command` 优先外部目录；模型误传 managed ID 时由 Application 改用最近添加的 external grant，审批计划与执行必须使用同一选择规则。

## 不采用的方案

- **把 Electron Renderer sandbox 当命令沙箱**：它不约束 Main 启动的本地进程。
- **只检查 cwd 或路径前缀**：不能防御绝对路径、`..`、符号链接、TOCTOU 和子进程逃逸。
- **命令黑名单**：Shell 组合、解释器和平台差异使黑名单不可封闭；实验模式允许任意命令语法，改用逐次人工确认标示风险。
- **用户选择目录即永久同意所有副作用**：持久授权仅覆盖该目录普通文件读写，不覆盖删除、高风险修改、联网、命令、提权或外部应用。
- **每个新任务都重置为请求审批**：会反复丢失用户明确选择。首个任务仍安全默认“请求审批”，之后只继承同一登录账号最近一次显式选择；已有任务不被账号偏好反向覆盖，关键危险和边界违规仍拒绝。

## 结果

优点：权限边界可解释；模型厂商无关；低风险开发操作可连续执行；人工确认与执行事实可审计。

代价：需要跨平台原生 helper、run 暂停/恢复、SQLite migration、审计 UI 和较大的安全测试矩阵；Windows 沙箱实现与签名/安装复杂度显著上升。

## 未决事项

- macOS 与 Windows 的具体沙箱机制、helper 语言和发布签名；
- 允许的最小系统运行时与包管理器集合；
- 域名代理如何处理 DNS rebinding、企业代理和自签证书；
- OS 沙箱完成后是否按命令能力进一步细分自动批准策略；
- Linux 是否进入后续平台范围。

这些问题由 [Phase 9 OS 沙箱技术 Spike](../reports/phase-9-os-sandbox-spike.md)关闭。“帮我批准”现按用户确认的产品语义自动放行文件写入、删除和宿主机命令；这显著扩大了 Prompt 注入和误操作风险。实验性 `run_command` 不得被描述为沙箱或发布级安全能力。
