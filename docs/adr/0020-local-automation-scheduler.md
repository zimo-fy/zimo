# ADR 0020：应用存活期本地 Automation 调度

## 状态

已接受。

## 决策

Automation 使用独立持久化模型和专用会话。专用会话保存模型、Agent、Workflow、Skill、知识库与 MCP Tool 绑定，执行时复用 ConversationService，因此能力解析、安全校验、取消和模型调用只有一条实现链路。

删除 Automation 只停止并软删除调度配置；已有消息的专用会话继续作为历史任务保留，避免删除计划时丢失执行上下文。尚未产生消息的空会话随配置清理。配置删除后，保留的会话解除“自动化专用会话不可单独删除”的限制，用户可从任务列表自行删除。

首版调度器只在 Electron Main 进程存活且账号已登录时运行，每 30 秒检查一次到期任务。支持单次、固定分钟间隔、每天和每周；固定间隔从保存或重新启用时开始计时。每天、每周和每日执行时间范围按设备本地时区计算，范围包含边界并允许跨午夜。

同一 Automation 最多一个 running 记录。领取任务时以 `next_run_at` 做事务级比较并写入下一次时间，避免重复执行。应用异常退出遗留的 running 记录在下次启动时标记失败。错过多个周期时只补一次，不回放整个积压。

固定间隔落在每日时间范围外时暂停，到下一个范围开始时刻执行，并从该次执行重新计算间隔。单次、每天和每周的计划时刻如果不在每日范围内，则在保存阶段拒绝配置，避免创建永远不会执行的任务。

任务按登录账号隔离；账号切换、退出登录或应用退出时取消已接纳的执行。普通日志仅记录任务 ID、运行 ID、状态和安全错误码，不记录指令、模型正文或 Tool 参数值。

## 边界

- 不注册操作系统服务，也不承诺应用关闭后的准点执行。
- 不自动选择 Router 目标；能力必须由用户显式绑定。
- 不允许并行重入同一任务。
- 不新增通用 Shell、任意命令或绕过 Skill/MCP 审核边界的执行能力。

2026-10-12 浏览器增量：Automation 专用会话继承账号级内建浏览器能力，不再保存关闭标记作为执行限制。该能力仍只在应用存活且账号登录时工作，模型必须支持 Tool Calling；共享 Profile 的模型浏览器操作按运行互斥，冲突返回可重试错误。登录失效、验证码和安全验证不在后台等待人工输入；招聘 Skill 应停止并报告待人工处理，但调度器暂没有独立的 `needs_input` 终态，模型正常回复仍可能记为 completed。浏览器网页动作按 ADR 0024 的用户决策不作逐动作审批，但这不改变 Shell、Skill 或 MCP 的原有边界。

## 后果

用户能够在应用内创建可审计的本地自动化，并在对应专用会话查看执行上下文。若未来需要关机后调度、多设备协调或服务端执行，必须另立 ADR，定义租约、时区、幂等、秘密托管和通知投递模型。
