# ADR-0009：本地知识检索与 Embedding 模型边界

状态：已接受（2026-09-03）

## 背景

Phase 6 需要让知识库从 UI 原型升级为可用的本地检索，同时保留后续数据库、内部管理后台和 Agent 引用的扩展路径。知识文件可能包含敏感业务数据，不能默认发送给外部 Embedding 服务。

## 决策

1. 文件解析、分块、索引与检索在 Electron Main 的受控 Adapter 中完成，Renderer 只使用具名 IPC；
2. 原文件复制到应用管理目录，SQLite 仅保存元数据、文本块和向量；删除文档或知识库时同步清理管理副本；
3. 关键词检索使用 SQLite FTS5 trigram；语义检索使用固定 revision 的 `Xenova/bge-small-zh-v1.5` INT8 模型和 512 维归一化向量；
4. 模型以固定 revision 的量化 ONNX 资源随安装包分发，开发态从项目资源读取，打包态从 `process.resourcesPath` 读取；启动后校验资源哈希并对既有文本块回填向量，不提供运行时下载入口；
5. 模型不可用时保持 FTS 检索，不把知识库整体判为不可用；模型可用时以 Reciprocal Rank Fusion 融合关键词和余弦相似度排名；
6. 文本块最多 480 个字符、重叠 64 个字符，保留页码、幻灯片、工作表和最近标题等来源信息；
7. Phase 6A–6B 先提供独立检索台；Phase 6C 仅在会话显式选择或 Agent 明确绑定时注入受限知识上下文，并持久化不含正文的来源快照。数据库和管理后台仍不连接。

## 安全边界

- 一次最多导入 20 个文件，单文件最多 20 MB；允许格式使用扩展名白名单；
- 拒绝符号链接、非普通文件、非法 UTF-8、压缩炸弹规模的归档内容和超时解析；
- Office/PDF 解析关闭 OCR、附件提取、iframe、原始内容和图片提取；
- 拖放时本地路径由 sandboxed Preload 的 `webUtils.getPathForFile` 获取，路径不返回 Renderer；
- 模型锁定完整上游 revision，并对配置、Tokenizer 和 ONNX 维护逐文件 SHA-256；资源不匹配时禁止加载并降级到 FTS5。

## 后果

- 离线数据不离开本机，中文业务语义检索无需外部 API Key；
- 安装包增加约 23 MB 模型资源，不再需要首次联网下载；不同机器的 CPU 推理延迟仍有差异；
- 当前向量在 SQLite 中进行线性扫描，适合本地中小规模知识库；数据量增长后再评估 sqlite-vec/HNSW，避免现在引入原生扩展发布成本；
- 文件解析和索引目前由 Main 编排。进入大文件或后台同步阶段前应迁移到 Utility Process，并加入任务进度、暂停与断点恢复；
- 数据库和后台同步应实现独立 Source Adapter，通过相同规范化文档入口进入分块/索引，不能让 Renderer 获得数据库凭据。
