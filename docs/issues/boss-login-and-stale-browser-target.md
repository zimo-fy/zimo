# Boss 登录误判与跨轮浏览器标签页 ID 失效

## 症状与影响

2026-10-09 的推荐牛人任务中，模型打开 Boss 后立即要求用户扫码；用户确认已登录后能进入推荐牛人页。模型给出方案并收到用户选择后，首次 `browser_snapshot` 报“浏览器标签页已关闭”，任务失败。

## 证据与根因

- 首轮 `browser_tabs` 仅返回 `about:blank`。模型导航至 Boss 登录地址后立即截图；实际截图仍是“BOSS 加载中”，没有登录表单或扫码证据。下轮同一标签页已进入 `/web/chat/recommend`。原 Skill 登录流程把“没有已登录业务标签页 + 发出导航 + 截图”误当成需要登录，模型也没有用快照验证加载后的状态。
- 第二轮已有由 `browser_tabs` 返回的真实标签页 ID。用户选择方案后，模型却给 `browser_snapshot` 传入一个此前从未由 `browser_tabs` 返回的 ID。适配器对所有未找到 ID 的情况都显示“标签页已关闭”；Tool Loop 直接终止，无法让模型重新取标签页。日志不能证明真实标签页已关闭。

## 修复

- Boss 源 Skill 登录流程改为等待加载后的 URL/页面结构，最多再等一次，只有明确出现扫码界面时才请用户登录。用户回复或选择方案后，Skill 必须重新 `browser_tabs` 并 focus 实际返回的 Boss 标签页，不跨轮沿用或编造 `targetId`；旧参考文件中的错误文案也对齐当前错误码。通用 Tool Loop 不注入 Boss 登录或页面状态判断。
- 应用数据中已安装的用户 Skill 副本和远端市场包不由仓库代码修改覆盖；源 Skill 文案需要对应包更新并重装后才生效。
- `BROWSER_TARGET_NOT_FOUND` 改为“指定的浏览器标签页不存在”。Tool Loop 将前两次此类错误作为结构化工具结果反馈模型，提示重新 `browser_tabs`；第三次继续抛错，避免无界循环。不会猜测或自动替换目标标签页，不改变其他 Tool 错误和审批边界。

## 回归与剩余风险

单测覆盖 Boss 源 Skill 的加载后登录判定、跨轮重新取标签页，以及错误 ID → `browser_tabs` → 真实 ID 重新快照的工具链路。真实 Boss 页面加载和模型遵循 Skill 指令仍需用户在本机 Profile 人工复测。模型可能再次违反 Skill 指令；错误恢复上限确保不会无限尝试。
