# 删除自动化误删已执行任务会话

## 现象与影响

删除自动化配置后，已执行的任务从左侧任务列表消失，无法再查看对话与执行结果。2026-10-12 本机数据库只读核对发现两条受影响会话的 `deleted_at` 均被写入，但消息表仍分别保留 2 条和 4 条消息；这是软删除，不是消息物理清除。修复代码不会自动修改已有用户数据库。

## 根因

`AutomationService.delete` 在软删除调度配置后无条件调用 `ConversationService.delete`，把专用会话也标记为删除。之前的侧栏同步修复使列表立即读取数据库，因而原本被缓存掩盖的历史会话消失问题直接显现。任务列表只展示有消息的会话；空专用会话不应作为普通新任务草稿遗留。

## 修复与边界

- 删除前读取专用会话并检查是否仍在运行；运行中拒绝删除，避免执行与配置删除竞态。
- 删除配置时保留已有消息的会话，使执行历史仍在左侧任务列表；仅清理从未产生消息的空会话。
- 保留的会话不再受自动化管理限制，可由用户从任务列表自行删除。确认文案明确说明保留策略。
- 不自动恢复旧数据库中已软删除的会话；恢复前须确定目标、备份与应用退出状态。

## 回归与剩余风险

Application 单测覆盖已有消息保留、空会话清理及运行中拒绝删除；既有侧栏同步测试继续覆盖刷新通知。历史用户数据需单独恢复，真实应用中删除与侧栏保留行为仍需人工验收。
