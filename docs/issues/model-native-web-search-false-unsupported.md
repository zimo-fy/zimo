# 原生联网测试误报“未执行搜索”

- 日期：2026-09-22
- 范围：模型设置页“测试原生联网”、Main 的原生搜索适配器

## 现象与影响

`deepseek-v4-flash` 通过已配置的 `/v1/messages` 网关测试时，界面可能提示“当前模型未执行原生联网搜索”。这条提示不能区分模型自行跳过搜索与搜索工具已经运行、但只返回错误的情况，用户无法据此判断配置是否可用。

## 证据与根因

对相同网关做仅输出字段类型的脱敏诊断：请求返回 HTTP 200，响应可包含 `server_tool_use`、`web_search_tool_result` 及有效 `web_search_result`；工具错误也会作为数组成员 `{type: "web_search_tool_result_error"}` 返回。未输出或保存原始响应正文、密钥、完整 URL。

原实现未设置 `tool_choice`，由模型自行决定是否搜索；同时只识别对象形式的工具错误，忽略数组内的错误。若一次响应只含数组包裹的搜索错误，就会被误判为“未执行搜索”。原始失败请求的响应未留存，无法确认用户这一次具体触发的是哪一种情况。

## 修复

在只暴露一个原生搜索工具的请求里设置 `tool_choice: {type: "any"}`。该网关已通过脱敏实测接受此参数并返回真实工具调用。解析器同时识别对象和数组形式的搜索错误；无工具调用、工具调用但全是错误、工具调用但无有效来源分别返回不同的安全错误。仍不把纯文本回答判定为联网成功，也不自动改用其他搜索后端。

## 回归与剩余风险

先加入失败测试，覆盖强制工具参数、数组内部分错误及仅错误的响应；再验证通过。测试使用虚构密钥，不连接真实服务。网关仍可能临时故障或无有效来源；界面测试只能证明本次请求有来源，不能证明来源内容准确。生产应用需重启后用已保存模型配置再次测试。公开资料应通过 `web_fetch` 核实。
