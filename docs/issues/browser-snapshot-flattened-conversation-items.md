# 浏览器快照平铺导致会话项无法与求职者信息关联

## 症状与证据

2026-10-10 的 Boss 回复任务已进入 `/web/chat/index`，浏览器快照成功且 `truncated=false`。左侧会话列表先连续输出多个匿名 `listitem` ref，姓名、岗位和消息预览却在后面的 `StaticText` 行出现。模型无法证明某个姓名属于哪个可点击 ref，因此没有点击求职者。页面并非缺少这些文字，也不是字符预算耗尽。

## 根因与修复

原解析器按 `Accessibility.getFullAXTree` 返回数组顺序平铺每个节点，没有沿 `childIds` 输出父子关系。CDP 数组顺序不保证父节点与其文本子节点相邻。参考 xclaw 的树遍历方式，解析器现按 `childIds` 深度优先输出并以有界缩进表示层次；未关联或缺少 ID 的节点仍保留为顶层，避免丢失页面事实。继续保留既有 ref 快照作用域、受保护值隐藏、重复文本过滤、节点/字符预算和 iframe 独立 ref。

## 回归与剩余风险

单测用“所有会话项先于所有文本”的 CDP 顺序验证姓名、岗位和预览归入正确 `listitem`，并覆盖嵌套编辑器标记、既有 iframe/ref 和预算行为。真实 Boss 页面的 `childIds` 层次仍需在用户已登录浏览器中复测；如果站点的可访问性树本身不把文字挂在会话项下，需要另行设计受控 DOM 补充，而不能让模型猜匿名项或放开任意 selector。
