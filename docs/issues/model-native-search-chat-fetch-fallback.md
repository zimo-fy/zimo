# 模型原生搜索不支持时会话无法继续读取网页

- 日期：2026-09-22
- 范围：普通会话、Workflow Agent 的联网工具执行；不改变模型设置页原生搜索能力测试

## 现象与影响

账号已选择“当前模型原生搜索”作为 `web_search` 后端时，模型能调用 Zimo 的 `web_search`，但网关可能不执行原生 `web_search_20250305`。会话直接显示“当前模型未执行原生联网搜索，不能仅凭文本回答判定为支持”，模型不再有机会调用仍然可用的 `web_fetch` 读取已知网页。

## 证据与根因

原生适配器在未观察到 `server_tool_use` 时正确抛出 `MODEL_NATIVE_SEARCH_UNSUPPORTED`，避免把模型文字误判为搜索来源。此前 `web_search` 工具直接传播这个错误；受控 Tool 执行器和模型工具循环随之结束本轮运行。先添加的离线回归测试复现了相同错误，并确认第二轮 `web_fetch` 从未执行。

## 修复与边界

仅会话中的 `web_search` 工具捕获明确的 `MODEL_NATIVE_SEARCH_UNSUPPORTED`，返回 `ok=false/status=unavailable`、空结果和安全的后续指导。模型可在下一轮调用 `web_fetch` 读取已知可信公开 URL，或说明无法核实；不能把猜测的网址和纯文本答复当作搜索结果。未配置搜索服务、原生传输/鉴权失败、无有效来源和取消继续按原错误处理。模型设置页原生搜索测试不经过这一工具层，仍要求真实工具调用及有效来源。

没有配置其他搜索 Provider 时，`web_fetch` 只能读取已知地址，不能发现未知页面；这不是完整搜索能力。仍不自动切换 Tavily、Brave 或 SearXNG。普通日志与审计不记录查询、URL 或正文，开发态敏感 payload capture 仍按既有规则处理。

## 回归与剩余风险

模型工具循环测试覆盖“原生搜索不支持 → 结构化不可用结果 → 下一轮 `web_fetch` → 最终回答”，并覆盖其他原生搜索故障仍抛错。定向 11 项测试、全仓 379 项单元测试、45 项集成测试、typecheck、lint、Desktop production build 和 1 项模型记忆 Electron E2E 通过。全仓格式检查仍有 8 个本次未修改文件的既有差异。

真实模型是否选择可靠 URL 及实际网页内容质量需人工验证；模型也可能选择不读取网页而如实说明无法核实。工具结果提示本轮不要重试搜索，但模型如果忽略提示，仍可能重复发起原生搜索。不得把没有实际读取的网页描述为已验证来源。
