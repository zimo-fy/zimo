# 浏览器启动改用非零 CDP 端口

## 现象与影响

Zimo 原先以 `--remote-debugging-port=0` 启动独立 Profile 浏览器。Chrome 在该启动方式下会将 `navigator.webdriver` 标记为 `true`；这是网站能够读取的自动化信号，但不能据此断定某次网站验证由它触发。近期鱼泡页面截图仅显示登录注册页，尚无明确的拦截证据。

## 原因与修复

原启动流程依赖 Chrome 在端口为 0 时写入的 `DevToolsActivePort`。按用户要求改为非零端口后，该文件不能再作为新进程的端点发现来源，因此同时调整启动与连接链路：

1. 从系统取得空闲回环端口，将非零端口传给浏览器；保留独立 Profile 和回环绑定。
2. 只接受本次浏览器子进程 stderr 报告、且端口与所选端口相同的 CDP WebSocket 地址。
3. 对 `/json/version` 中的 `webSocketDebuggerUrl` 做精确比对后连接；验证通过再将端点保存至仅用户可读的 Profile 文件，供应用重启后复用。
4. 启动失败、超时、取消或端点不符时终止子进程，不退回旧的 `port=0`，也不连接同端口的其他浏览器。

## 验证与剩余风险

解析器单测覆盖正确端点、错误端口和非回环地址；Browser CDP 单包类型检查、相关测试及格式/静态检查见 `PROGRESS.md`。本机临时 Profile 的 Chrome headless 已验证非零端口与 `/json/version` 端点一致；可见窗口、Windows Chrome/Edge 和鱼泡实际访问结果仍需人工验收。

端口申请与浏览器绑定之间仍存在短暂竞争窗口；若被占用，启动会失败而不是误连。非零端口并不保证网站不会识别或限制 CDP 自动化，且本变更不绕过登录、验证码或站点政策。
