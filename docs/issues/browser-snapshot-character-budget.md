# 浏览器快照 30,000 字符导致招聘列表截断

## 症状与证据

2026-10-09 的 Boss 推荐牛人任务中，加载后的快照连续返回 `truncated=true`，正文约 29,982–29,996 字符。页面包含 iframe 候选人列表；后续滚动后年龄文本不再出现在快照中，最后两次快照正文相同。可交互元素数量约 697–843，无法仅凭它证明是否触及 2,000 原始节点上限，但正文紧贴 30,000 字符边界，确定字符预算已耗尽。缺失的年龄字段也可能来自站点未加载或未暴露，不能全归因于截断。

## 调整

- 浏览器 Accessibility 快照总字符预算由 30,000 提至 150,000，保留 2,000 节点、16 个 iframe、受保护字段隐藏和仅为已输出元素建立 ref 的边界。
- 受控 Tool 仍默认限制序列化输出 100,000 字符；只对 `zimo.browser.snapshot` 和 `zimo.browser.wait` 放宽到 350,000，以容纳最多 150,000 字符正文的 JSON 转义及元数据。其他工具不变。
- Boss、鱼泡推荐牛人 Skill 中原有的 30 次列表滚动硬上限改为 10 次；猎聘原有 15 次规则不在“30 → 10”范围内，未改动。详情滚动、按键次数和超时数值不变。

## 验证与剩余风险

自动测试覆盖超过旧 30,000 字符的新快照、150,000 字符截断边界、浏览器 Tool 输出例外与其他 Tool 仍拒绝超限，以及 Boss/鱼泡 Skill 的 10 次标记。大快照会增加模型请求 token、延迟和开发态 payload 日志体积；2,000 节点限制仍可能先触发。当前仍按整棵 AX 树顺序读取，未实现候选人列表或单卡聚焦快照，需真实页面人工复测。
