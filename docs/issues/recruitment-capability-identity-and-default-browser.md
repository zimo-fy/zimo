# 招聘能力精确加载、默认浏览器与标题兜底

状态：已修复
日期：2026-10-08

## 症状与影响

- 统一招聘首次按 `zimo.boss-zhipin` 精确搜索未命中，第二次关键词搜索才加载成功；
- 普通会话没有手动打开浏览器时，模型看不到 `browser_*` Tool；
- 首轮回答成功后，标题附加请求超过五秒便保留“新对话”，后续轮次不再自动重试。

## 证据与根因

Skill Store 使用目录 ID 派生 `zimo.market.*` 作为安装来源身份，下载时未保留包内声明的稳定 `packageId`。能力发现只比较安装来源身份，因此编排 Skill 提交的稳定 ID 无法匹配。

浏览器能力此前默认关闭，只有会话持久化的 `browserEnabled=true` 才注入工具。标题服务则在主回答刷新后同步等待一次独立模型请求，并用五秒本地定时器主动取消；失败后没有本地兜底。

## 修复

- Skill Store 继续用 `skillPackageId` 保存商城安装身份；能力发现从已持久化的 `SKILL.md` frontmatter 读取并校验稳定编排身份，不修改商城更新/卸载身份。精确身份重复时拒绝动态加载，避免歧义。
- 新建普通会话默认启用浏览器；数据迁移只更新非 Automation 会话，Automation 保存时仍显式关闭。Workflow 和无前台 owner 的运行仍不会获得浏览器 Tool。
- 标题服务移除自身五秒定时器，等待模型正常返回并继续响应会话取消；模型失败或返回空标题时，从首条用户指令生成有界本地标题。标题失败仍不改变主回答的成功状态。

## 回归覆盖与剩余风险

单元测试覆盖 Store Skill 稳定 ID 精确命中与重复拒绝、标题失败兜底、新会话浏览器默认值。SQLite 集成测试覆盖既有普通会话启用和 Automation 会话保持关闭。

模型网关仍保留统一的外部请求超时和取消边界；标题服务不再额外施加更短的五秒限制。普通前台会话默认暴露浏览器工具增加了模型可操作独立 Profile 的范围，用户仍可在会话“+”菜单关闭，URL、快照、密码、审计和 Workflow/Automation 隔离规则不变。
