# 手动压缩错误跨会话显示

## 现象与影响

在仅有少量历史消息的会话中手动压缩，界面提示“较早的完整消息不足，暂时无需手动压缩。”；随后新建或切换到其他会话，提示仍留在消息输入区。压缩检查本身针对原会话，错误展示却误导了其他会话。

## 证据与根因

Electron 回归测试先在会话 A 触发该提示，再新建会话 B：修复前 B 的 `role="alert"` 仍显示原提示。`ChatPage` 用单个页面级 `error` 状态显示所有会话的操作错误；切换 `conversationId` 时未清除它。手动压缩的 IPC 请求异步完成，原会话的失败结果还可能在切换后重新写入同一状态。

## 修复与验证

- 错误提示记录来源会话 ID，只在选中该会话时显示；切换到其他会话不会显示旧提示。
- 手动压缩的异步回调沿用发起时的会话 ID，即使结果在切换后返回，也不会显示到新会话；会话详情仍按现有 ID 检查更新。
- 新增 Electron 回归用例，覆盖历史不足提示后切换到新会话；用例在修复前失败，修复后通过。

## 剩余边界

本次将消息输入区的错误展示按会话隔离。其他操作的异步失败会沿用其发起时的页面会话 ID；若操作所传的会话 ID 与页面选中 ID 不一致，仍需在该操作处单独核对来源。
