# 新会话首条长回复未自动贴底

状态：已修复（待桌面端人工验收）
日期：2026-10-10

## 现象与影响

新建任务发送第一条指令后，AI 流式回复起初未超出消息区；回复增长到出现纵向滚动条时，视口留在上方，用户必须手动滚动才能继续阅读。后续用户消息通常会重新定位底部，因而首轮更明显。

## 证据与根因

`useConversationAutoScroll` 原先只在会话 ID 或用户消息数量变化时调用 `scrollImmediately`；`message.delta` 只增长助手正文，不改变这两个依赖。消息区虽设置底部 `overflow-anchor`，但从无溢出进入溢出时，浏览器锚定并不能保证视口持续贴底。已有 `isStickyRef` 只被写入，未用于内容增长后的校正。

## 修复与回归

- 观察消息内容和消息区的尺寸变化；仅在原本处于贴底状态时即时校正位置。自动校正不用平滑动画，避免流式回复期间的动画叠加和抖动。
- 增长触发的滚动事件先于尺寸观察回调到达时，不将其误判成用户主动上翻。用户在稳定内容上主动上翻后，后续增长不再拉回。
- 新增组件回归测试，覆盖首条回复首次溢出、增长滚动事件先到、输入区压缩消息区高度，以及主动上翻后的继续增长。

## 验证与剩余风险

定向回归测试、变更文件 ESLint/Prettier 与桌面构建通过。全仓 TypeScript 检查仍被未修改的知识库类型错误、缺失模块及 Renderer 现有类型错误阻断；相邻会话测试的一项旧用例因缺少 `TooltipProvider` 失败。真实桌面窗口的首条长回复与滚动条拖动行为仍需人工验收。
