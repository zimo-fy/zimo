# 浏览器快照噪音与 CDP 失败诊断

## 症状与证据

Boss 推荐牛人任务的快照达到 30000 字符上限并标记 `truncated`。2026-10-08 的本地运行中，一份快照包含约 241 行 `InlineTextBox`、约 571 行空 `generic`；模型在可见候选人未匹配时过早请求用户选择。随后针对 iframe `RootWebArea` ref 的滚动运行约 15 秒，最终仅显示通用 `BROWSER_CDP_FAILED`，无法从原日志判断失败的 CDP 方法。

## 原因与处理

原快照序列化将重复文本碎片计入节点与字符预算。参考 xclaw 的通用过滤，仅跳过 `InlineTextBox`、`LineBreak`、纯装饰 `StaticText`，以及名称已被未忽略的父节点完整包含的 `StaticText`/`emphasis`。过滤在预算计数之前执行；不删除空 `generic` 或其 ref，避免抹掉可能的滚动容器或无标签交互目标。姓名、岗位、条件、安全提示等唯一文本仍保留。

CDP Adapter 对命令失败记录 `browser.cdp.command.failed`：仅含经过格式限制的方法名、固定枚举的失败原因与耗时。原始异常消息、URL、页面内容、参数和凭据不进入普通日志。用户可见错误及取消语义保持不变；诊断回调失败不得替代原始浏览器错误。

## 回归与剩余风险

单测覆盖重复文本在预算前过滤、唯一候选信息和空容器 ref 保留，以及 CDP 超时、断线和未知错误的安全分类。未对真实 Boss 页面做端到端快照比较；页面结构可能变化，需在用户登录后确认是否仍截断、关键候选信息与按钮是否完整。此改动**不**解决 iframe 内滚动容器定位、模型过早提问或通用错误文案；下一次失败应根据新事件的方法/原因继续定位，不应据此推断浏览器已退出。
